## 两条必须先读的原则

无论使用还是二次开发，下面两条最容易踩坑。

### 1. 一切硬件事实都在运行期探测

生产代码里**不允许**出现具体型号、驱动版本、绝对路径、模型文件名、主机名。
探测失败显示「未知」，组件缺失显示「未安装」，**绝不填充默认值**。

这样换机器、换框架、换硬件时都不需要改代码。

### 2. 框架不支持的接口要"明确不采集"，而不是"采集失败"

如果控制台去探测当前框架不存在的接口，会产生大量 stale 告警，
看起来像控制台坏了，实际只是框架能力不同。

控制台会根据框架识别结果**裁剪能力**，并在界面上说明差异。
详见 [架构设计](ARCHITECTURE.zh-CN.md)。
